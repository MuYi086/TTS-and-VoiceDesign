# 音频空间化细节讨论

本文总结 TTS 音频采样率、声道、WAV 母带、MP3 导出、空间化和 HRTF（Head-Related Transfer Function，头相关传递函数）之间的关系，并结合 `TTS-and-VoiceDesign` 项目当前模型输出给出推荐工作流。

## 一、核心结论

对于需要脚步移动、耳边低吟、左右定位、前后空间感和混响的有声剧，推荐采用以下流程：

```text
TTS 模型按原生采样率生成单声道人声
        ↓
按项目混音采样率统一导入
        ↓
加入脚步、环境声、混响、声像和 HRTF 空间化
        ↓
导出 48 kHz 双声道 WAV 母带
        ↓
最后导出 192～256 kbps 双声道 MP3
```

需要特别注意：

1. TTS 模型主要负责音色、发音、语速、情绪、气息和表演方式，不负责可靠地生成“从左边移动到右边”或“从后方绕到耳边”的空间定位。
2. TTS 输出保持单声道是正常的。空间定位应该在后期混音阶段完成。
3. 24 kHz 转成 48 kHz 主要是统一后期工程和兼容插件，不会凭空增加 24 kHz 音频中原本没有的高频细节。
4. WAV 可以保存双声道，但 WAV 本身不等于双声道；如果输入是单声道，直接转换为双声道通常只是复制左右声道，不会自动产生空间感。
5. MP3 应该在所有空间化和混音处理完成后最后导出。WAV 或 FLAC 更适合作为母版和后期处理格式。

## 二、采样率、码率和位深不是同一个概念

### 2.1 采样率（sample rate）

采样率表示每秒记录多少个声音样本：

| 采样率 | 理论最高可记录频率 | 常见用途 |
|---|---:|---|
| 16 kHz | 约 8 kHz | 电话音质、语音识别、部分语音模型 |
| 24 kHz | 约 12 kHz | TTS 人声、旁白、语音内容 |
| 44.1 kHz | 约 22.05 kHz | 音乐和通用消费音频 |
| 48 kHz | 约 24 kHz | 影视、音效、后期制作、空间音频 |

最高频率约等于采样率的一半，这是奈奎斯特频率（Nyquist frequency）。因此，24 kHz 音频并不是“音质减半”，而是最高频率范围低于 48 kHz。

人声的主要信息通常集中在 12 kHz 以下，所以 24 kHz 对 TTS 人声一般已经足够。48 kHz 对音乐、环境声、复杂音效和后期滤波更有余量。

### 2.2 MP3 码率（bitrate）

例如 `-b:a 192k` 表示 MP3 平均每秒使用约 192 kbit 数据。码率主要决定压缩强度和文件大小：

- 码率越高，文件越大，压缩伪影越少；
- 码率越低，文件越小，但可能出现发闷、金属感、水波纹感或高频失真；
- 码率不是采样率，也不代表音量或音调。

6 分 10 秒（370 秒）音频的 MP3 体积大致为：

| MP3 码率 | 预计大小 |
|---:|---:|
| 96 kbps | 约 4.4 MB |
| 128 kbps | 约 5.9 MB |
| 192 kbps | 约 8.9 MB |
| 256 kbps | 约 11.8 MB |
| 320 kbps | 约 14.8 MB |

纯人声可以考虑 128 kbps；包含背景音乐、脚步和复杂环境声的有声剧建议 192～256 kbps。

### 2.3 位深（bit depth）

位深表示每个采样点的数值精度，例如 16-bit、24-bit 和 32-bit float。它和采样率无关。

当前项目实际生成的 WAV 多数是 16-bit PCM。16-bit 对最终发布通常足够；如果进行大量多轨混音、增益调整和效果处理，可以在 DAW（数字音频工作站）中使用 32-bit float 作为中间处理格式，最终母带导出 24-bit PCM WAV。把已经是 16-bit 的素材简单转换成 24-bit，不会恢复丢失的细节。

## 三、`TTS-and-VoiceDesign` 当前输出情况

根据项目 API、worker、模型配置和仓库内已有实际 WAV 文件检查，当前结果如下：

| 模型 | 当前实际输出采样率 | 声道 | 位深/编码 | 说明 |
|---|---:|---|---|---|
| `dots.tts-soar` | 48 kHz | 单声道 | 16-bit PCM WAV | API 配置为 48 kHz，worker 会将波形整理为单声道 |
| `VoxCPM2` | 48 kHz | 单声道 | 16-bit PCM WAV | 配置中有内部 16 kHz 和输出 48 kHz；当前 worker 实际写出 48 kHz |
| `LongCat-AudioDiT` | 24 kHz | 单声道 | 16-bit PCM WAV | 代码要求模型采样率为 24 kHz，并将参考音频和输出整理为单声道 |
| `Qwen3-TTS` | 24 kHz | 单声道 | 16-bit PCM WAV | 模型配置为 24 kHz，worker 合并输出时使用单声道 |
| `MiMo TTS` | 由云端返回 | 由云端返回 | 由云端返回 | 项目代码保留云端 WAV 的首个分块参数，当前没有本地样本可供检查 |
| `MOSS-SoundEffect v2` | 48 kHz | 单声道 | 16-bit PCM WAV | 当前本地声效样本实际为 48 kHz 单声道 |

VoxCPM2 配置中的：

```text
sample_rate = 16000
out_sample_rate = 48000
```

需要区分内部音频 VAE（变分自编码器）处理采样率和最终输出采样率。当前项目通过模型运行时采样率写出 WAV，实际输出为 48 kHz。

## 四、24 kHz 和 48 kHz 的音质关系

24 kHz 人声转成 48 kHz 后：

- 采样点数量增加；
- 文件更适合进入 48 kHz 混音工程；
- 可以兼容更多现成插件；
- 时长应保持不变；
- 不会产生原始 24 kHz 音频没有的 12 kHz 以上真实细节。

因此，24 kHz 的 LongCat 或 Qwen3-TTS 人声并不一定比 48 kHz 的 VoxCPM2 人声“差一半”。模型声码器、音色还原、失真、噪声和表演稳定性往往比采样率更影响听感。

如果模型原生只支持 24 kHz，不建议在请求中伪造或强行指定 48 kHz。当前 LongCat worker 会检查 24 kHz；Qwen3-TTS 通过模型返回采样率。将 `-ar 48000` 放在 ffmpeg 后处理阶段，属于重采样，不是让模型以 48 kHz 重新生成。

## 五、为什么最终混音仍建议使用 48 kHz

48 kHz 不是空间化处理的硬性要求，24 kHz 也可以做左右声像、音量变化、延迟、滤波、混响和部分 HRTF 处理。

推荐 48 kHz 的主要原因是：

1. 项目中的 dots、VoxCPM2 和 MOSS-SoundEffect 已经是 48 kHz；
2. 影视、游戏、音效和空间音频工作流普遍使用 48 kHz；
3. 现成插件和 HRTF 数据库更常见地支持 44.1 kHz、48 kHz 和 96 kHz，24 kHz 兼容性相对少；
4. 48 kHz 给混响、延迟、滤波和空间移动留出更多高频处理余量；
5. 所有音轨统一采样率后，时间轴、插件和导出流程更容易管理。

HRTF 本身并不天然绑定 48 kHz。理论上可以有 24 kHz 的 HRTF，也可以有 48 kHz、96 kHz 的 HRTF。关键是输入音频、HRTF 脉冲响应和处理工程的采样率必须正确匹配。很多插件会在内部自动重采样；如果插件不支持 24 kHz，则应在进入插件前统一转为 48 kHz。

## 六、单声道、双声道和空间化

### 6.1 WAV 双声道的含义

双声道 WAV 分别保存左声道和右声道。如果左右声道内容不同，才能表现左右空间差异。

把单声道直接使用 `-ac 2` 转成双声道，通常只是：

```text
左声道 = 原单声道
右声道 = 原单声道
```

这不会自动生成左、右、前、后或绕头移动效果。

### 6.2 普通立体声和 HRTF

普通立体声主要适合表现：

- 左侧；
- 中间；
- 右侧；
- 从左到右的声像移动。

“从后方传来”“绕到右耳边”“贴着头皮低吟”等前后、上下和近耳效果，使用 HRTF 或双耳空间化（binaural spatialization）更合适。双耳处理通常在耳机上更明显。

HRTF 通过左右耳的时间差、音量差和频谱变化模拟声音来自不同方向。24 kHz 仍然可以使用 HRTF，但由于最高频率约为 12 kHz，部分依赖高频耳廓特征的定位线索可能少一些；48 kHz 兼容性和高频余量通常更好。

## 七、悬疑场景的正确制作方式

### 7.1 脚步从后方移动到右侧

不要让 TTS 模型负责脚步的空间位置。推荐：

1. 用 MOSS-SoundEffect 单独生成脚步素材；
2. 保持脚步素材为单声道，方便后期定位；
3. 在混音工程中自动化左右声像；
4. 用音量、低通滤波、早期反射和混响表现远近与走廊空间；
5. 如果要求明确的后方绕头效果，使用 HRTF，而不只是普通左右平衡。

### 7.2 女鬼在耳边低吟

VoxCPM2 等 TTS 模型的 `control_instruction` 可以描述发声方式，例如：

```text
声音极轻，气声明显，近距离耳语，低沉缓慢，带有不稳定的呼吸
```

这些描述负责声音的表演和质感。以下内容应该交给后期空间化：

```text
从左后方移动到右耳边
在听者脖子旁边说话
绕着头部移动
从身后贴近
```

可以在后期加入 HRTF、轻微左右延迟、距离滤波、近距离混响和声像自动化。不要只把这些空间指令写进 TTS 提示词后期待模型可靠生成双耳定位。

## 八、推荐的实际工作流

### 8.1 仅拼接同一模型的人声

如果所有片段都来自 LongCat 或 Qwen3-TTS，可以先在 24 kHz 单声道下拼接，再统一转换一次到 48 kHz：

```bash
ffmpeg -i all_24k_mono.wav \
  -af "aresample=resampler=soxr:precision=28" \
  -ar 48000 \
  all_48k_mono.wav
```

此时仍然是单声道，只是完成了采样率统一。

### 8.2 进入空间化混音工程

推荐在混音工程中统一设置：

```text
采样率：48000 Hz
内部处理：32-bit float
人声轨道：mono
音效轨道：按素材原始声道导入
空间化输出：stereo
```

如果只是简单输出格式，可以使用：

```bash
ffmpeg -i mixed_audio.wav \
  -ar 48000 \
  -ac 2 \
  -c:a pcm_s24le \
  master.wav
```

但只有在已经完成实际声像或空间化混音后，`-ac 2` 才有意义。若输入仍是单声道，它只会复制左右声道。

### 8.3 最后导出 MP3

有声剧建议：

```bash
ffmpeg -i master.wav \
  -c:a libmp3lame \
  -b:a 192k \
  final.mp3
```

如果背景音乐和复杂音效较多，可以使用 `256k`。MP3 应作为交付或播放副本，WAV 母带仍应保留。

## 九、常见误区

### 误区一：48 kHz 一定比 24 kHz 清晰

不一定。48 kHz 可以保存更高频率，但如果源模型只生成了 24 kHz 内容，升采样不会恢复新细节。

### 误区二：把单声道转双声道就有空间感

不对。空间感来自左右声道的差异、时间差、滤波、混响和 HRTF，而不是声道数量本身。

### 误区三：TTS 模型可以直接生成“左耳”“后方”的声音

通常不可靠。TTS 应负责声音表演，空间位置应由后期处理完成。

### 误区四：每个片段都单独转码很多次没有影响

重复重采样和重复 MP3 编码会增加处理损失。建议保持 WAV，统一采样率一次，MP3 最后编码一次。

### 误区五：HRTF 只能使用 48 kHz

不对。HRTF 可以有不同采样率版本，但插件兼容性和高频定位余量使 48 kHz 成为更方便的工程选择。

## 十、最终建议

对当前项目最稳妥的做法是：

1. LongCat、Qwen3-TTS 按原生 24 kHz 单声道生成；
2. dots、VoxCPM2、MOSS-SoundEffect 保持当前原生 48 kHz 单声道输出；
3. 不在 TTS 克隆请求中强行要求空间位置或双声道；
4. 在后期混音入口统一到 48 kHz；
5. 保持 TTS 人声轨道为单声道，使用混音器决定空间位置；
6. 对普通左右移动使用声像自动化；
7. 对前后、耳边和绕头效果使用 HRTF 或双耳空间化；
8. 输出 48 kHz 双声道 WAV 作为母带；
9. 最后使用 192～256 kbps 双声道 MP3 作为发布文件；
10. 在导出后使用 `ffprobe` 检查采样率、声道数、位深和时长。

检查最终文件：

```bash
ffprobe -v error -select_streams a:0 \
  -show_entries stream=sample_rate,channels,channel_layout,bits_per_sample,codec_name,duration \
  -of default=nw=1 master.wav
```
